01 · why this exists

Every published NIDS paper does this differently — or not at all.

Feature-importance leakage, class-homogeneity artifacts, resplit falsification — each has been demonstrated in isolation, in one-off research notebooks tied to one dataset. IDS2Eval turns the methodology into config-driven software you run on your own data.

Status quo

A one-off analysis notebook

Re-derived per paper, per dataset. Findings aren't reusable, and rarely open-sourced in a runnable form.

Generic tools

AutoML (PyCaret, AutoGluon, TPOT)

Breadth of algorithms, but no IDS-specific data-quality checks — leakage and homogeneity aren't in scope.

IDS2Eval

Config-driven, IDS-specific, reusable

12 checks + 14-classifier benchmark from one YAML file. Point it at a CSV, get a finding with a status and a number.

03 · the checks

Twelve checks. Each returns a status and a number.

Not a vague quality score — {check, status, summary, details}, where a flag or warning names the specific, checkable signature behind it. Full writeup for all 12: AUDIT_CHECKS.md.

v1 · always on
dedup_check

Exact feature-space duplicates within and across train/test — memorization, not generalization.

v1 · always on
leakage_screen

Fits a fast RandomForest and inspects its own feature importances to catch shortcut learning.

v1 · always on
identity_column_flag

Standalone predictive power of IP/port/MAC-like columns you declare as identity columns.

v1 · always on
low_cardinality_warning

Flags identity-like columns with suspiciously few unique values relative to the split.

v1 · always on
homogeneity_test

Nearest-neighbor distance vs. a same-set control, to separate real leakage from inherent class homogeneity.

v1 · always on
resplit_falsification

A session/time-grouped resplit that makes session-correlated leakage structurally impossible, then compares accuracy.

v1 · always on
class_distribution_report

Per-class counts, shares, and imbalance ratio — before and after dedup.

v1 · always on
schema_fingerprint_check

Matches known feature-extractor signatures (e.g. CICFlowMeter) and surfaces that extractor's documented bugs.

v1 · always on
data_integrity_check

Missing labels, missing or constant/near-constant features, and ±infinity values.

v2 · opt-in
synthetic_realism_check

Trains a domain classifier to distinguish this dataset from a reference real-traffic sample.

v2 · opt-in
cross_dataset_drift_check

Trains on this dataset, evaluates on a reference dataset in a unified feature space.

v2 · opt-in
known_issue_lookup

A curated table of documented per-dataset problems, matched on dataset.name.

Selected findings, on real data

flag — real finding

leakage_screen

Fits a fast RandomForest and inspects its own feature importances. Independently reproduced Flood et al. 2024's finding that Destination Port alone hits near-perfect accuracy across CIC-IDS2018 — confirmed on the real, official distribution.

ok — settled by experiment

resplit_falsification

A session-grouped resplit that makes session-correlated leakage structurally impossible. On CIC-IDS2018's near-saturation accuracy, the grouped resplit reproduced the random split's accuracy to within 0.003 percentage points.

flag → ok after dedup

dedup_check

Exact feature-space duplicates between train and test. On real UNSW-NB15 data: 42% train duplication before cleanup, correctly dropped to 0% after — measured twice, not assumed.

warning — real shift

class_distribution_report

Per-class counts and imbalance ratio, before and after dedup. On UNSW-NB15 the ratio shifted from 2:1 to roughly 1:1 after deduplication — duplicated rows were disproportionately one class.

05 · configure it

One YAML file. No code required for the common case.

Every field is documented in configs/schema.yaml; worked examples in CONFIGURATION.md.

# my_config.yaml
dataset:
  name: my-dataset
  raw_files: ["data.csv"]
schema:
  label_column: Label
preprocessing:
  dedup: true
  sampling:
    binary: [none, smote, smoteenn]
classifiers:
  list: [RandomForest, XGBoost]
  tuning: true
random_seed: 42
06 · scope

What this deliberately doesn't do.

A working-baseline prototype with disclosed tradeoffs, not a hidden limitations paragraph.

Out of scope, on purpose

  • Feature engineering — imputation, feature selection, dimensionality reduction. IDS2Eval audits and benchmarks the features you give it; it doesn't invent new ones.
  • The staged-cascade detection architecture from this project's companion research paper is intentionally excluded here — this tool ships the reusable audit/benchmark methodology, not the novel architecture.
  • Scaling comparison — preprocessing.sampling supports comparing multiple strategies in one run; scaling is still single-valued.
  • known_issue_lookup ships with two seed entries. Extending the curated table is open-ended, ongoing work.
