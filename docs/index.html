01 / THE QUESTION

What did the model actually learn?

A classifier can learn both network behaviour and properties of how a dataset was constructed. IDS²Eval helps researchers separate those effects so model results are easier to interpret and defend.

Did it learn the attack, or did it learn how the benchmark was built?
IDS²Eval challenges the conditions behind the metric.

Duplicates. Identity fields. Temporal shortcuts. Flow-group overlap. Class homogeneity. Known dataset defects. The goal is not another quality score; it is evidence you can inspect.

03 / 18 CHECKS

Specific checks, not one vague score.

Each check names a specific, falsifiable concern and emits a status, summary and supporting details. Start with the threat family, then drill into the individual checks only when needed.

C01

Duplicate & overlap checks

Detect exact feature-space duplication within and across partitions.

C02

Label conflicts

Find identical feature vectors that map to contradictory labels.

C03

Leakage screen

Use fast predictive importance to expose suspiciously dominant features.

C04

One-rule challenge

Ask whether one shallow rule already explains too much of the label.

C05

Identity columns

Measure the standalone predictive power of IP, port, MAC and similar identifiers.

C06

Port + protocol shortcut

Test whether a trivial pair of network fields acts as a class proxy.

C07

Temporal leakage

Check whether time alone is predictive enough to expose scenario structure.

C08

Flow-group leakage

Detect the same declared flow identity on both sides of the split.

C09

Resplit falsification

Re-evaluate under a grouped split that structurally blocks session-correlated leakage.

C10

Known-issue lookup

Surface curated, published limitations associated with the named benchmark.

C11

Schema fingerprinting

Match columns to extractor signatures with documented calculation problems.

C12+

Distribution, realism & drift

Class balance, homogeneity, synthetic realism, cross-dataset drift, seed sensitivity and core data-integrity checks complete the suite.

A note on dataset creators

Designed to help researchers get more reliable results from valuable benchmark datasets.

NIDS datasets are the backbone of ML and DL research. They are difficult, expensive, and often foundational community contributions. IDS²Eval is meant to help researchers use those datasets more carefully, identify structural quirks, understand where shortcuts may appear, and train models whose performance is easier to defend. The goal is to strengthen the value of these datasets, not to diminish the work behind them.

07 / SOFTWARE FREEDOM

Free as in free speech, not free beer.

IDS²Eval is AGPLv3 free software. Use it, study it, modify it, redistribute it, and use it commercially. The point is not to prevent commerce; it is to preserve the same freedoms for the people who receive or interact with modified versions.

For an auditing tool, that reciprocity is part of the design: the software and its modifications should remain inspectable.
