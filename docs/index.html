01 / Why audit first

A high score can still come from a weak benchmark.

A classifier score can reflect attack behaviour, dataset construction, or both. IDS²Eval checks the dataset and split conditions before benchmarking.

01 / CONTAMINATION

Did train and test really stay separate?

Exact duplicates and repeated flow identities can place effectively familiar traffic on both sides of a split; separate near-duplicate checks expose confusable samples.

Checks include duplicate overlap, flow-group leakage and grouped resplit falsification.
02 / SHORTCUTS

Did the model learn a shortcut?

Ports, addresses, timestamps, collection order and a single dominant feature can become class proxies even when the model appears accurate.

Checks include identity columns, temporal leakage, one-rule challenge and feature-AUC ranking.
03 / FRAGILITY

Would the conclusion survive a stronger setup?

Some results move when the split, seed, feature set, scenario or deduplication policy changes. IDS²Eval can measure that sensitivity directly.

Opt-in stress tests include scenario holdout, repeated seeds, cross-capture and result robustness.

04 / Audit checks

28 checks for specific failure modes.

Each check returns a status, summary and details. The scorecard links those findings to the run evidence. Nineteen checks are enabled by default and nine are opt-in.

C01

Duplicate & overlap

Exact feature-space duplicates within and across train/test.

C02

Label conflicts

Identical feature vectors mapped to contradictory labels.

C03

Flow-group leakage

Declared flow identities that appear on both sides of the split; no-ops when no flow-ID columns are configured.

C04

Leakage screen

Fast model importance to expose suspiciously dominant features.

C05

One-rule challenge

A depth-1 tree tests whether one simple rule already explains too much.

C06

Identity columns

Standalone predictive power of declared IP-, port-, MAC- and similar identity columns.

C07

Temporal leakage

When a timestamp column is declared, tests whether time alone acts as a class proxy for collection scenarios.

C08

Grouped resplit

When group columns are available, re-evaluates under a split that blocks session-correlated leakage.

C09

Scenario holdout

When a scenario column is declared, tests generalization with one collection scenario held out.

C10

Result robustness

Compares performance across available split, dedup and feature-set conditions.

C11

Data integrity

Missing labels or feature values, constant or near-constant features, and infinite values.

C12

Known issues & fingerprints

Curated dataset facts and feature-extractor signatures with documented defects.

05 / Workflow

One config, one recorded run.

The CLI and local dashboard use the same core pipeline. The dashboard opens with a pre-filled starter config.

01

Load & validate

Load CSV, Parquet, CSV-formatted .txt, compressed CSV, or a named CSV/Parquet member from ZIP. Then validate the schema and fingerprint the data.

02

Audit raw data

Run enabled checks before deduplication and save the untouched evidence.

03

Apply configured preprocessing

Deduplicate when enabled. Then rerun data-dependent checks and reuse structural findings.

04

Benchmark classifiers

Run the configured binary and optional attack-type benchmarks across the selected scaling and sampling strategies.

05

Preserve

Write scorecards, benchmark detail, fingerprints, environment and run status.

07 / Benchmarking

Benchmark after the evaluation conditions are visible.

The registry contains 14 supported classifiers, including stacking and voting ensembles. Runs can include binary detection and, when configured, attack-type classification, with accuracy, weighted F1, macro F1, AUC, training time, inference time and per-class metrics.

RandomForestXGBoostDecisionTreeNaiveBayesLogisticRegressionKNNSVMLDAStackingVotingExtraTreesHistGradientBoostingAdaBoostMLP

Fold-local preprocessing when tuning

When tuning is enabled, scaling and sampling stay inside the imbalanced-learn pipeline passed to GridSearchCV, so they are fitted independently inside each CV fold.

Evidence beyond one metric

Benchmark outputs include confusion matrices, per-class precision/recall/F1, feature importance where supported, best hyperparameters when tuning runs, and class distributions before/after sampling.

A result you can inspect, cite and reproduce.
